# Dataset v1 Report

**Dataset version: 1.0.0 (scaffold). Actual collected/annotated samples: 0.**

## 1. Dataset objective

Produce a validated, annotated, leakage-free, YOLO26-compatible train/validation/test dataset for real-time multi-animal hazard detection (`snake`, `monkey`, `dog`, `person`) on educational-campus CCTV, ready to hand to Task 5 for model training.

## 4. Annotation methodology

See `docs/research/annotation-guidelines.md` for the full standard. Summary: CVAT for bounding-box annotation, tightest-practical boxes, partial/occluded objects annotated when identifiable, hard negatives given no label, person boxes carry no identity information, snake sub-category (venomous/non-venomous/unknown) recorded as metadata only, never as a detection class.

## 5. Annotation format

Ultralytics YOLO: `class_id x_center y_center width height`, normalized `[0,1]`, zero-indexed class IDs from `configs/classes.yaml`.

## 6. Quality control

Two-stage: automated validation (`scripts/dataset/validate_images.py`, `validate_yolo_labels.py`, `check_class_ids.py`, `check_bbox_coordinates.py`, `check_image_label_pairs.py`) followed by human review, with priority review for snake/small/low-light/occluded/blurred examples. See `docs/research/data-quality-policy.md`.

## 7. Duplicate handling

SHA-256 exact-duplicate detection (quarantined, dry-run by default, `--apply` required to actually move files) plus perceptual-hash near-duplicate flagging (review only, never auto-removed). Implemented in `scripts/dataset/detect_duplicates.py`.

## 8. Leakage prevention

Group-aware splitting: every image is assigned a `group_id` (source video/sequence, or source dataset) before any split decision, and whole groups — never individual frames — are assigned to train/val/test. See `docs/research/dataset-splitting-policy.md` for the full policy and a worked verification example.

## 9. Split strategy

Target 70/15/15 (`configs/dataset.yaml`), group-aware, with the **actual** achieved ratio always reported rather than forced. Current sentinel_v1: 0 images in every split — nothing to report yet.

## 10. Environmental diversity

Metadata fields for lighting, weather, time-of-day, and region exist (`scripts/dataset/schemas.py`, inherited from Task 3) but 0 samples currently carry real values.

## 11. Hard negatives

`datasets/raw/hard_negatives/` (Task 3) and the `empty_label_policy` (Task 4) are both in place to support hard-negative images (rope, hose, cable, shadow, etc. with no label). 0 hard-negative samples collected yet.

## 12. Limitations

- **This is a pipeline-readiness report, not a populated-dataset report.** Every count is genuinely 0.
- The full 12-step pipeline (`validate_images.py` → `generate_dataset_report.py`) was built and **verified against synthetic test data** — a simulated two-camera, 12-image, 11-label dataset with two distinct video sequences — which confirmed: image/label validation correctly passes clean data, class ID / bbox checks correctly find zero issues, group assignment correctly identified 2 sequences + 2 singletons, and — critically — the split step kept both entire video sequences (6 frames and 4 frames) within a single split each, never splitting a sequence across train/val/test. That synthetic data was removed after verification; it is not part of this dataset version.
- `data.yaml` was structurally validated against the Ultralytics YOLO dataset-YAML convention (`path`, `train`, `val`, `test`, `names`, all relative paths). A live `from ultralytics import YOLO` load-and-validate check (`scripts/dataset/verify_yolo_dataset_load.py`) requires the full Task 1 environment (torch + ultralytics) and should be run there once real data populates the dataset — Task 1 already confirmed `yolo26n.pt` loads successfully in that environment.
- No model accuracy, precision, recall, or mAP is reported anywhere in this document, because none has been calculated — that is Task 5 scope.

## 14. Reproducibility information

The complete generation path — raw source → Task 3 metadata → CVAT annotation export → the 12 numbered scripts in `scripts/dataset/` → `sentinel_v1` — is scripted and documented. Given the same annotated CVAT export and the same `--seed` to `create_dataset_split.py` (default 42), the pipeline produces a deterministic, reproducible split. No step in the pipeline mutates `datasets/raw/` or `datasets/processed/annotated/` — everything downstream is a copy (`shutil.copy2`), preserving the original source data.
